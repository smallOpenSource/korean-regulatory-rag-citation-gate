# PRD-04 User Scenarios

## Scenario 1: 아침 후속 조치 점검 (Junior PB)
1. PB 로그인 → 대시보드에서 긴급/높음 후속 조치 건수 확인.
2. 대시보드의 "국내 시장 데이터 상태"에서 기준시각(source_as_of), 신선도, 품질이 준비 완료가 아니면
   시장 데이터가 차단/주의 상태임을 먼저 확인한다.
3. 후속 조치 관리함 이동 → 우선순위 순 카드 목록 확인.
4. 만기 임박 고객 카드 선택 → AI 스크립트 토글 확인.
5. 고객 통화 완료 → 후속 조치 상태를 완료로 전환.
6. 후속 상담 예약 → 상담 워크스페이스 이동.

## Scenario 2: Consultation Workspace (Senior WM)
1. 고객 360 진입 → AI 브리핑 패널에서 고객 요약 확인.
2. 상단 합성 고객 고지와 포트폴리오 `valuation_source`를 확인한다. 실제 국내 시세
   기준시각(source_as_of)/품질 정보가 없으면 합성 보유 평가액으로만 설명한다.
3. 하우스뷰 패널에서 현재 활성 하우스뷰 참조.
4. 포트폴리오 격차 차트에서 자산배분 괴리 확인.
5. 상담 노트 작성.
6. 적합성 확인 + 설명의무 확인 체크 → 완료 버튼 활성화.
7. (백로그/현재 계약 아님) 이메일 초안 에이전트 호출 → 후속 이메일 초안 생성 → 검토 후 발송 승인. 현재 구현 API에는 이메일 초안/발송 경로를 포함하지 않는다.

## Scenario 3: Monthly House View Cycle (Admin)
1. 운영자가 `scripts/run_batch_pipeline.sh --profile full-mvp --all-stages --report ...`를 실행해 시장/거시 데이터 수집 또는 SKIPPED/FAILED 차단 증거를 남긴다.
2. 운영자가 하우스뷰 생성 에이전트를 수동 트리거.
3. 초안 생성됨 → 운영자 검토.
4. 검토 대기 → 활성 전환(운영자 액션).
5. 이후 전체 상담에 활성 하우스뷰 자동 참조.
6. 이전 하우스뷰 → 대체됨으로 자동 처리.

## Scenario 4: Aftercare Event (ELS KI)
1. 배치/제공자 증거가 현재가 확인 성공 또는 공급자 차단 상태를 `batch_job_logs`에 남긴다.
2. 녹인 조건 충족 → 사후관리 이벤트 진행 필요 생성.
3. 녹인 후속관리 업무가 긴급 우선순위로 자동 생성.
4. PB가 후속 조치 관리함에서 긴급 알림 확인.
5. 고객 긴급 연락 → 상담 노트 기록.
6. 사후관리 이벤트 해결 처리.

## Scenario 5: RAG Q&A (Product/Regulation)
1. PB가 RAG Q&A 패널에서 "ELS knock-in 후 고객 설명의무 범위" 질문.
2. 하이브리드 검색으로 OpenDART 공시 + 규정 문서 청크 검색.
3. (현재 안전 차단) 검색/생성이 완성되기 전까지는 차단 응답과 준비 상태/주의 문구만 표시한다. 향후 GPT-mini가 검색 청크 기반 답변 + 인용을 생성한다.
4. 신뢰도가 낮으면 주의 문구 표시.
5. PB가 출처 문서 원문 링크 확인 가능.
